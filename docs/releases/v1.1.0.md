# v1.1.0 — 蓝牙 App 式生命周期 + 电台/蓝牙模式切换

**发布日期**：2026-10-26
**对比版本**：`v1.0.0-amp-working` → `v1.1.0`
**固件版本宏**：`PROJECT_VER = "1.1.0"`（启动日志会打印 `firmware v1.1.0`）

---

## 一句话总结

把蓝牙做成**像手机 App 一样可以独立「开启 / 关闭 / 释放」**，
并让**电台与蓝牙模式通过串口命令切换**（上电不再自动进电台）。

---

## ✨ 新增功能

### 1. 蓝牙完整生命周期（串口命令）
| 命令 | 语义 | 行为 |
|---|---|---|
| `bt open`（同 `bt mode` / `bt on`） | **开启** | 停掉电台 + 启动蓝牙协议栈；冷启动（释放后完整重建）或热启动（关闭后秒级恢复），恢复后自动设为可连接 + 可被发现 |
| `bt close`（同 `bt off`） | **关闭** | 断开手机 + 关控制器（射频完全让出），**协议栈与内存保留**，可秒级重开 |
| `bt free` | **释放** | 整个协议栈拆除：音频任务优雅退出 → A2DP/AVRC 反初始化 → Bluedroid 卸载 → 控制器反初始化 → 释放 16KB 环形缓冲。**全部蓝牙内存归还堆**，命令会打印释放前后的堆值 |

### 2. 模式切换（串口控制，上电不自动进电台）
- 上电后设备停在**蓝牙待命**状态，控制台提示：
  ```
  ready. bluetooth: waiting for a phone. radio: play <n>  ('help' = all commands)
  ```
- `play <n>` / `next` / `prev` → **进电台模式**（自动关闭蓝牙，射频归电台 + WiFi）
- `stop` → 电台会话结束，**自动恢复蓝牙**（回到待命）

### 3. 射频让渡对称化
| 当前模式 | 射频归谁 | 另一路状态 |
|---|---|---|
| 蓝牙模式 | 蓝牙独占 | WiFi 彻底关闭（`esp_wifi_stop`） |
| 电台模式 | WiFi/电台独占 | 蓝牙彻底关闭（`esp_bt_controller_disable`） |

### 4. 状态可观测
- `bt` 命令新增电源状态：`bluetooth : idle (power: on / closed / released)`
- `status` 命令新增固件版本：`firmware: v1.1.0 (build Oct 26 2026 15:42:10)`
- `help` 首行显示固件版本

## 🔧 改进

- **电台模式改为彻底释放蓝牙**：原 `bt_player_close()` 只关控制器（协议栈仍占 40KB 堆），改为释放，避免电台 18KB 缓冲与蓝牙栈抢堆导致崩溃重启
- **电台音频缓冲改为堆上动态分配**：播放时 `malloc`、停止时 `free`，不再占用静态 DRAM
  → **DRAM 静态占用 87.9% → 73.5%，腾出 17.5 KB**
- **开机默认音量改为 40**：`CONFIG_RADIO_INITIAL_VOLUME`，并固化到 `sdkconfig.defaults`
- **音量持久化改为条件编译，默认关闭**：需要记忆上次音量时打开 `CONFIG_RADIO_VOLUME_PERSIST=y`
- **调试打印精简**：统计日志间隔 2 秒 → 30 秒（`BT_STAT_INTERVAL_US`）；每包回调/波形 dump 由 `BT_VERBOSE`（默认 0）控制

## 🐛 修复

- **蓝牙丢块喀哒声**：环形缓冲加**高水位回落**（积压 >90% 丢最老数据压回 45%），把"每秒碎丢"变成"偶尔跳帧"
- **上电第一次自动重连必掉**：A2DP 连接回调里同步执行阻塞操作（`radio_stop_and_release()` ~1s + `esp_wifi_stop()` ~几百 ms）卡死 AVDTP 信令；改为回调只置标志 + `xTaskNotifyGive`，重活挪到音频任务
- **蓝牙连不上**：消费者任务错绑 core 0 且优先级 21 > BTC(19) 饿死蓝牙栈；改为绑 **core 1**（应用核）
- **电台破音回归**：RMS 自动增益改回**峰值归一化**（目标峰值 ≤30000），消除 32767 硬削波

## 📋 串口命令速查（模式相关）

```
bt                查蓝牙状态（含电源：on / closed / released）
bt open|mode      开启蓝牙：停电台 + 启动协议栈，等手机连
bt close|off      关闭蓝牙：断手机 + 关控制器（栈保留，秒级重开）
bt free           释放蓝牙：协议栈卸载，内存全部归还堆
bt disc           断开当前手机

play <n>          进电台模式（自动关闭蓝牙）
next / prev       切台（电台模式）
stop              停电台（自动恢复蓝牙）

vol [0-100]       查/设音量（蓝牙和电台共用）
status            系统状态（含固件版本）
```

## ⚠️ 升级注意事项

1. **上电不再自动播电台** —— 这是行为变更。想听台请敲 `play <n>`（或先 `list` 看台号）。
2. **电台模式期间手机搜不到/连不上设备** —— 预期行为（蓝牙彻底关闭以让出射频）。`stop` 或 `bt open` 即恢复。
3. **音量默认 40 且不记忆** —— 重启回到 40。如需记忆上次音量，配置 `CONFIG_RADIO_VOLUME_PERSIST=y`。
4. **音量两路叠加** —— 设备音量（`vol`）× 手机音量。若声音过大，先把 `vol` 设到 100（等价于只由手机控制）再逐步回调。日志中 `clip` 正常应恒为 0。

## 🔍 排查要点（给后来人）

**出现喀哒声/杂音，先查硬件再调软件：**

- ✅ **共地必须接牢** —— 功放 GND 与 ESP32/电源 GND 接触不良是本次喀哒声的**真正元凶**。
  地线虚接时音频回流路径阻抗随电流变化，叠加出宽带脉冲杂音，空闲和播放时都有。
  **接牢共地后声音即正常。**
- ✅ **功放独立供电** —— 建议 5V。从 3.3V 轨取电时峰值 400–800mA 会把轨拉塌，
  导致载波被压扁（"嗤嗤"声、只在开关瞬间有声）。

**软件侧的坑：**

- 蓝牙回调（跑在 BTC 任务里）**绝不能做阻塞操作**，否则卡死 AVDTP 信令 → 手机超时断链。
  正确做法：回调只置标志 + `xTaskNotifyGive`，重活交给音频任务。
- 音频消费者任务**必须绑 core 1**（蓝牙栈 BTC/HCI/控制器都在 core 0），
  否则高优先级会饿死 BTC(19) → 蓝牙连不上。
- 环形缓冲不要开太大 —— 32KB 环会与蓝牙栈抢堆，导致
  `host_recv_pkt_cb couldn't acquire memory` 断言崩溃。保持 16KB。

## 📦 发布流程（下次发版照这个做）

### 第 1 步：改版本号

编辑顶层 `CMakeLists.txt`：

```cmake
set(PROJECT_VER "1.2.0")     # 按改动性质决定加哪一位
```

版本号怎么定（语义化版本 `MAJOR.MINOR.PATCH`）：

| 改动类型 | 加哪一位 | 例子 |
|---|---|---|
| 修 bug（向后兼容） | PATCH | `1.1.0 → 1.1.1` |
| 新增功能（向后兼容） | MINOR | `1.1.0 → 1.2.0` |
| 行为/命令不兼容变更 | MAJOR | `1.1.0 → 2.0.0` |

### 第 2 步：更新 CHANGELOG.md

在文件顶部（第一个 `---` 之前）插入新的一节：

```markdown
## [1.2.0] - 2026-MM-DD

### 新增
- ...

### 修改
- ...

### 修复
- ...
```

### 第 3 步：提交 + 打标签

```powershell
cd f:\ESP32-WROOM\esp32-fm\esp32_max98357_fm
git add -A
git -c user.name="user" -c user.email="user@example.com" commit -m "v1.2.0: 简述改动"
git -c user.name="user" -c user.email="user@example.com" tag -a v1.2.0 -m "v1.2.0: 发布说明"
```

> 这两处的 `vX.Y.Z` 必须和 CMakeLists 里的 `PROJECT_VER` 一致。

### 第 4 步：打包合并固件（供他人直接烧录）

```powershell
  --flash_mode dio --flash_freq 40m --flash_size 2MB `

  0x8000 build\partition_table\partition-table.bin `
  0xe000 build\ota_data_initial.bin `
  0x10000 build\esp32_max98357_fm.bin
```

### 第 5 步：推送分支和标签

```powershell

```

### 第 6 步：在 GitHub 网页创建 Release

1. 打开 `https://github.com/yilantingfengye/esp32wroom-bt-fm/releases/new`
2. **Tag**：选刚推上去的 `v1.2.0`

4. **描述**：从 `docs/releases/vX.Y.Z.md` 复制正文
5. ☑️ 勾上 **设置为最新版本**
6. 在「资产」区域**上传合并固件 `.bin`**（这步别漏！）
7. 点 **发布发行版**
